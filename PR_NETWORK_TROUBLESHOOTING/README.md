## 1. Мета роботи
Ознайомитися з базовими інструментами діагностики мережі в Windows та Linux, навчитися перевіряти мережеві інтерфейси й DNS, а також перехоплювати й аналізувати мережевий трафік за допомогою сніфера `tcpdump`.

## 2. Хід виконання та результати

### Рівень 3 бали: Базова перевірка мережі у Windows
У командному рядку Windows (CMD) виконано перевірку трьох рівнів доступності:
1. `ping 127.0.0.1` — перевірка локального стека TCP/IP (**localhost / loopback**): затримка `<1 ms`, `0% loss`.
2. `ping 8.8.8.8` — перевірка прямого з'єднання з мережею Інтернет за **IP-адресою** (без використання DNS): середня затримка `71 ms`, `0% loss`.
3. `ping google.com` — перевірка роботи **DNS-сервера** та доступності вузла за **доменним ім'ям** (`142.250.120.100`): середня затримка `104 ms`, `0% loss`.

![Windows CMD ping](screen1_windows_ping.png)

### Рівень 4 бали: Troubleshooting у Linux (Ubuntu)
В середовищі Ubuntu встановлено пакети `net-tools` та `dnsutils`, після чого виконано діагностику:
* `ifconfig` — перевірено активні мережеві інтерфейси (`wifi0` з адресою `192.168.1.35` та `lo` `127.0.0.1`).
* `nslookup google.com` — перевірено розпізнавання доменного імені через DNS-сервер (`192.168.1.1#53`), отримано список IPv4 та IPv6 адрес Google.

![Ubuntu ifconfig та nslookup](screen2_linux_dns.png)

### Рівень 5 балів: Перехоплення та аналіз трафіку через `tcpdump`
Встановлено утиліту `tcpdump` та запущено перехоплення ICMP-пакетів (`sudo tcpdump -i any icmp -n -c 8`) одночасно з виконанням `ping -c 4 8.8.8.8`.

**Аналіз перехоплених пакетів:**
* **Протокол:** `ICMP` (працює поверх `IP`).
* **Запит (`Out` — `ICMP echo request`):** відправляється з локального інтерфейсу `eth0` (**Source IP:** `172.29.172.233`) на сервер Google (**Destination IP:** `8.8.8.8`), `length 64`.
* **Відповідь (`In` — `ICMP echo reply`):** надходить від сервера Google (**Source IP:** `8.8.8.8`) на локальний вузол (**Destination IP:** `172.29.172.233`) з тим самим ідентифікатором `id 2602` та номером послідовності `seq 1..4`.
* Втрати пакетів під час обміну склали `0%`, середній час відгуку (RTT) — `115.141 ms`.

## 3. Відповіді на контрольні питання
1. **Що перевіряє `ping`?** Перевіряє доступність мережевого вузла на 3-му (мережевому) рівні моделі OSI, вимірює час проходження пакетів туди й назад (RTT) та відсоток втрат.
2. **Різниця між `ping` IP і домену?** При зверненні за IP-адресою пакети одразу маршрутизуються до цілі, а при зверненні за доменом система спочатку робить DNS-запит для перетворення імені в IP-адресу.
3. **Що таке ICMP?** *Internet Control Message Protocol* — протокол керуючих повідомлень для діагностики мережі та передачі звітів про помилки доставки пакетів.
4. **Що показує `tcpdump`?** Перехоплює та виводить у реальному часі мережеві пакети з інформацією про час, інтерфейс, протокол, IP-адреси/порти відправника й отримувача та прапорці пакета.
5. **Як відфільтрувати пакети?** За допомогою виразів фільтрації після команди: за протоколом (`sudo tcpdump icmp`), за хостом (`sudo tcpdump host 8.8.8.8`), за портом (`sudo tcpdump port 53`) або їх комбінацією.
